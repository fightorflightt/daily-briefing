左侧按日期倒序显示目录，默认打开最新日期；右侧顶部使用“公众号、AI资讯、政策公告、每日复盘”四个分类标签。AI资讯保留 AI Builder、GitHub 精选、产品灵感、技术资讯分组；政策保留四个地区／主题分组；复盘展示当日文件中实际存在的每日、每周、每月栏目。保留完整已生成正文和原始链接，不再次调用模型改写。

公众号沿用现有采集、筛选、23:00 发布与 `data/YYYY-MM-DD.json` 数据。新增资讯单独导出到 `data/workbench/YYYY-MM-DD.json` 和独立日期目录，页面合并两份日期目录。这样公众号晚间更新不会覆盖上午发布的三类资讯，两边可以独立缺失并明确显示“尚未同步”。历史公众号数据和 aibuilder 信息源目录继续可用。

每天 10:00 的现有自动任务在生成并通过校验后，执行网站的 `scripts/publish-workbench.mjs`，只发布当日 `ai`、`zhengce`、`fupan` 三份文件的内容；上岸雷达仍保留在本地。当天本地文件完整时跳过生成，但仍检查网站是否需要同步。只有完整、日期正确、带有通过校验标记且条目数量一致的源文件才能导出。相同内容重复执行不产生提交；同步失败保留本地资讯并报告，不重新生成。

发布只使用当前 Git 登录状态，检查干净工作区、main 分支和固定远程仓库，使用互斥锁、快进同步和普通推送；发生并发冲突时停止并报告，不强推、不自动清理工作区。沿用现有 GitHub Pages 流程，不修改部署配置。用户已在本聊天确认网站修改及每日自动公开同步。

新增资讯的导出与发布命令（Node.js 标准库，无需安装依赖）：

```bash
node --test scripts/test-export-workbench.mjs
node scripts/export-workbench.mjs <笔记库绝对路径> [YYYY-MM-DD]
node scripts/publish-workbench.mjs <笔记库绝对路径> [YYYY-MM-DD]
```

`export-workbench.mjs` 用于本地验证和首次发布准备；定时任务调用 `publish-workbench.mjs`，要求网站仓库处于干净的 `main` 分支。发布脚本仅暂存当日新增数据与新增资讯日期目录，普通推送后进行有限次数的线上数据核对。部署未及时完成会明确报告“已推送但网站尚未更新”，不会误报已上线，也不会创建新的重试任务。遇到遗留锁、未推送提交、内容冲突或未提交改动时停止并保留现场，人工核对，不自动清理。
